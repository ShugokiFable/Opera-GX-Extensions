## Ad Shield logic validation

- General advertising rules and the YouTube ruleset can be enabled independently from each other and from the main security shield.
- General static and downloaded ad-domain rules exclude YouTube initiators, preventing the ordinary ad switch from silently controlling YouTube.
- HaGeZi Threat Intelligence and URLhaus data are compiled into the threat tier; HaGeZi Pro mini is compiled separately into the ad tier.
- Ad-only site exceptions outrank ad rules while remaining below tracking-parameter, threat, cryptomining, and local-network protections.
- YouTube Network-only mode does not register the YouTube recovery script and does not perform YouTube-specific cosmetic DOM changes.
- Adaptive and Aggressive YouTube recovery is registered only when selected, runs in Chromium's isolated extension world, and does not patch `fetch`, `XMLHttpRequest`, page globals, Media Source Extensions, or YouTube player-response objects.
- The YouTube ruleset does not blanket-block `googlevideo.com`, preserving ordinary playback paths that share the same media infrastructure.
- Anti-adblock fallback creates a session rule scoped to the triggering tab and YouTube initiators.
- The fallback rule outranks only Aegis ad rules. Threat, cryptomining, LAN-probe, and tracking-parameter protections remain above it.
- Temporary fallback state is removed on tab closure, module disable, reset, or manual resume.
- Badge state distinguishes main protection (`ON`), independent ad-only protection (`ADS`), relay routing (`RLY`), and fully paused state (`OFF`).
- Newly enabled threat or ad intelligence populates immediately when no compiled cache is available.

## Existing security regression tests

- Dynamic DNR batching and rule-priority separation.

- Fail-closed PAC routing contains no public `DIRECT` fallback.

- Proxy-auth credentials remain session-only and are returned only to a matching active challenger.
- Fatal relay failover candidates require a successful live probe before selection.

## Manual Opera GX checks still required

The build container cannot reproduce the user's Windows Opera GX profile or YouTube account experiments. Final interactive testing should cover:

- Loading or reloading the unpacked extension through `opera://extensions`.
- General ad shield on/off behavior on representative news, streaming, and commerce sites.
- Ad-only per-site exception behavior while threat protection remains active.
- YouTube module off, Network-only, Adaptive, and Aggressive modes.
- Temporary YouTube anti-adblock fallback and manual resume.
- Current YouTube server-side experiments, which can vary by account, region, session, and rollout cohort.
- Opera-specific privacy API ownership and conflicts with other blockers or enterprise policy.
- Live feed download and DNR compilation at current list sizes.

No browser extension can guarantee undetectable ad blocking or reliable removal of server-side inserted advertising. The implementation minimizes page-level modification in Network-only mode and isolates more invasive recovery behind explicit switches.
